# Encrypted daily offsite job

`scripts/esign_backup/daily_offsite.py --config /protected/config.json` runs the existing local backup as its existing user, then encrypts only the configured site's complete backup and seal keys using `encrypt_site_backup.sh`. It uploads ciphertext to `daily/` and `keys/`, with explicit SSE-S3, and reads every object back to verify SHA-256. Only a fully verified set advances the atomic success checkpoint.

Install scripts root-owned and non-writable by the application. Keep configuration, AWS credential JSON and public age recipients in a root-only directory. The private age identity stays offline, never on the server. The credential file contains only AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY and AWS_DEFAULT_REGION for the already restricted backup identity. Do not use the existing local script's plaintext `--upload` option.

Configuration keys: `local_user`, `container`, `bench_path`, `site_name`, `seal_key_subdir`, `bucket`, `expected_identity`, `credentials_file`, `recipients_file`, `encrypt_script`, `local_backup_script`, `out_dir`, `state_dir`, `state_file`, `lock_file`, `notifier`, `alert_target`. Deployment-specific values must remain outside this public repository. The notifier is the existing OpenClaw CLI with a configured Telegram account; a successful API receipt is recorded without recipient identifiers or message contents.

Replace exactly the existing daily local-backup cron line with this wrapper at the same schedule. It executes local backup first, so no guessed delay is needed. Preserve the previous crontab for rollback and avoid installing a second competing backup schedule. Host UTC 17:00 corresponds to 02:00 KST. The local script retains its original local-retention behavior. S3 expiration remains a bucket lifecycle responsibility; this identity must not gain deletion permissions.

`--upload-only` checks a recent existing snapshot without running local backup/cleanup. `--test-failure` sends a clearly labeled synthetic alert without changing production backups. A normal run rejects a snapshot older than the current job start (allowing clock rounding); upload-only allows six hours. A missing/incomplete set, modified ciphertext, identity mismatch, upload/download failure or missing version/encryption result prevents success. Do not remove a partial encrypted set automatically: investigate before retrying.

Verification: run `python3 -m unittest -v test_daily_offsite` from the script directory on Linux. Tests cover roundtrip/prefix separation, wrong identity, stale snapshot, tampered archive and download failure preserving the success checkpoint. Actual acceptance additionally requires a restricted-identity S3 roundtrip and Telegram receipt. An enabled cron is not proof that the next overnight run has happened; inspect the protected last-success timestamp after its first scheduled run.
