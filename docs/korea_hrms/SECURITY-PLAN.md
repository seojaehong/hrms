# SafeClaw HR — 에이전틱 보안 플랜 (2026-07-10, 어드바이징)

목적: "온톨로지+Hermes 하네스 HR SaaS"의 **장기 보안 로드맵**. 오늘 실증된 위협
(에이전트가 자체 셸로 3사이트 접근)을 출발점으로, 레이어별 위협모델과 완화를
고지(M1~M5)에 정렬한다. 원칙: **모델은 신뢰하지 않는다 — 신뢰는 하네스가 만든다.**

## 0. 레이어 모델
```
L1 LLM(gpt-5.5/…)      : 환각·프롬프트 인젝션·승인 위조 시도
L2 Hermes 런타임        : 자체 도구(셸·파일·웹)·세션 상태·OAuth 토큰 보관
L3 도구/MCP 계층        : 테넌트 스코프·확정행위 게이트·감사로그
L4 Frappe 데이터        : PII(주민번호)·급여·테넌트 격리·백업
L5 네트워크/인프라       : 포트 노출·방화벽·시크릿 보관
```

## 1. 현재 방어선 (구현·검증됨)
| 레이어 | 방어 | 검증 |
|---|---|---|
| L2 | **api_server toolset 완전 잠금**(`platform_toolsets.api_server: []`) | /v1/toolsets enabled 0 + 적대적 재스모크("DB 조회 불가" 자인) |
| L2 | gateway Bearer 키(600 파일)·격리 HERMES_HOME(기존 봇과 분리) | 무키 호출 거부 |
| L3 | tool_registry fail-closed(read_only=False + human_approved is not True → fn 미호출) | 스파이 테스트로 증명(랄프#1) |
| L3 | 신고서 fail-closed(human_approved 없이는 조회 0회) · 계산 전용 API 일관 | 테스트 |
| L4 | 주민번호 Password 암호화(+마스킹 자동파생, throw 없음) · 테넌트=사이트 격리 | 라이브 검증 |
| L4 | MCP 테넌트 토큰(sha256, `~/.korea-hrms-mcp/`) + 사용량 로그 | 운영 중 |
| L5 | 8130·8100 외부 차단(iptables REJECT + Oracle SL), 도커서브넷→8130만 개방 | 외부 curl 000 확인 |
| 프로세스 | 시크릿 push 전 스캔·public repo에 키/고객데이터 금지 | 40커밋 push 시 스캔 |

## 2. 갭과 로드맵 (우선순위순)

### P0 — M1 완주와 동시 (즉시)
1. **에이전트 도구 = MCP 단일 경로**: korea-hrms-mcp(:8100, FastMCP streamable HTTP+Bearer —
   Hermes `mcp_servers` url 규격 정합)를 Hermes의 유일한 도구로 등록. **테넌트별 토큰 스코프**
   — 에이전트 세션에 해당 테넌트 토큰만 주입(크로스 테넌트 구조적 차단).
2. **프롬프트 인젝션 1차 방어**: 하네스 시스템 프롬프트에 경계 지시 + 도구 결과/사용자 입력을
   데이터로 취급하는 서술(랄프#3 US-1). ⚠️지시만으로는 불충분 — 진짜 방어는 "도구가 스코프
   밖 행동을 못 함"(구조) — 1번이 본질.
3. **에이전트 감사로그**: run_agent_skill 호출·도구호출·최종응답을 테넌트별 append 로그로
   (기존 MCP usage.jsonl 패턴). 법적 증빙·사고 규명의 기초.

### P1 — 테넌트 노출 전 (M1 텔레그램 실전 전)
4. **PII 최소화**: 하네스가 LLM에 보내는 도구 결과에서 주민번호·계좌 등 원문 필드 차단
   (allowlist 직렬화 — 이름·금액·기간만). 특히 BYOK 아닌 platform 과금 시 외부 LLM으로
   나가는 데이터 명세를 문서화(개인정보 처리방침 연동).
5. **레이트리밋/쿼터**: 테넌트별 에이전트 호출 쿼터(기존 plans.py 쿼터 구조 재사용) —
   비용 폭주·DoS 방지.
6. **gateway 표면 축소**: API_SERVER_HOST를 0.0.0.0→도커 게이트웨이 인터페이스로 축소 검토
   (현재 외부는 방화벽이 막지만 심층방어).

### P2 — 확정행위 개통 전 (M4 전 필수)
7. **mutation 도구의 이중 게이트**: MCP 계층 human_approved + Frappe Draft 승인큐 —
   단일 실수로 뚫리지 않게 2중. 적대적 테스트(모델이 승인 위조) CI 상설화.
8. **OAuth 토큰 관리**: `.hermes-home/auth.json`(코덱스 리프레시 토큰) 백업 제외·권한 600·
   유출 시 폐기 절차 문서화. 제우스봇 auth와 절대 공유 금지(리프레시 충돌).
9. **온톨로지 무결성(M2)**: published 게이트 + validate-graph를 게이트에 편입 —
   에이전트가 지식노드를 직접 쓰는 경로 금지(draft 제안만).

### P3 — 스케일(1만 사업장) 전
10. 시크릿 매니저 도입(현재 env/site_config 산재 → Vault류 or 최소 sops), 키 로테이션 주기.
11. 침투 점검(외부)·프롬프트 인젝션 레드팀(내부 시나리오: 명세서 메모란에 지시문 심기 등).
12. 감사로그 보존정책·개인정보 위탁 문서(테넌트→우리→LLM/CODEF 2단 위탁) — 법무 검토.
13. 모델 출력 필터(전화·주민번호 패턴 마스킹) — 채널 발신 직전 최종 방어선.

## 3. 상시 규율
- 새 도구 등록 시 기본 read_only=True, mutation은 설계 리뷰 필수.
- 모든 잠금·게이트는 **적대적 테스트로 증명**하고 게이트 스위트에 남긴다(선언 금지).
- 배포 후 컨테이너 실파일 검증(에코 신뢰 금지 — 2026-07-10 함정).
- 사고 시: results.tsv 저널 + 에이전트 감사로그로 타임라인 복원 → 재발방지 테스트 박제.
