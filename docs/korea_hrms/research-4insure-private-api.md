# 한국 4대보험 사설/상용 API 리서치 및 Korea HRMS 연동 방안

- 작성일: 2026-07-10
- 대상: Korea HRMS (Frappe HRMS 포크, Python, Oracle Cloud 멀티테넌트)
- 현재 상태: 취득/상실/근로내용확인 신고서 xlsx 자동생성(`hrms/regional/south_korea/insurance_filing_api.py`, human_approved fail-closed) → 제출은 수동(EDI/토탈서비스)
- 목표: ① 자격/가입내역·고지보험료 **조회** ② 보험료 고지내역 **대사** ③ 가능하면 신고 **제출 자동화**

> 표기 규칙: **[확인]** = 공식 페이지/문서에서 확인, **[추정]** = 정황상 유력하나 미확인, **[미확인]** = 확인 실패·영업 문의 필요.

---

## 1. 결론 요약 (TL;DR)

1. **"신고 제출"을 공식 REST API로 열어주는 사설 업체는 확인되지 않았다 [미확인/사실상 부재]**. 공단 측(4대사회보험 정보연계센터, 건보 EDI, 고용산재 토탈서비스)도 민간 SaaS용 제출 API를 제공하지 않는다. 국내 급여 SaaS들도 전부 우회 구조다 — 뉴플로이는 **RPA + 온라인 팩스 접수**, 자비스는 **세무대리인 대행**, flex는 **Payroll Partners(BPO/전문가 제휴)**.
2. **조회(가입자명부·고지보험료·완납증명 등)는 사설 스크래핑 API로 충분히 가능**하다. 주요 후보: **CODEF(코드에프)**, **쿠콘(COOCON)**, **하이픈(HYPHEN)**, **틸코(Tilko)**. 모두 사업장 공동인증서(또는 간편인증)를 통한 스크래핑 방식.
3. **추천: Phase 1은 CODEF**(4대보험정보연계센터 사업장 가입자명부 API + 사회보험통합징수포털 완납/고지 API, Python SDK `easycodefpy` 존재, 데모 무료) — 소량 검증에는 **하이픈**(비즈머니 선불, 계약서 없이 즉시 시작, 월 10만원+건당)이 진입장벽이 더 낮아 PoC 대안으로 병행 검토.
4. **제출 자동화는 API가 아니라 '대행 구조'로 푼다**: 우리(노무사 사무소)가 건보·연금 **EDI 업무대행기관** + 고용산재 **보험사무대행기관(보험료징수법 §33)** 지위로 수임사업장 위임을 받아, HRMS가 만든 신고서를 우리 EDI 계정에서 일괄 제출. 장기적으로 EDI 웹 화면 RPA(agent-browser/Chrome 자동화)로 반자동화.

## 4. 법적/컴플라이언스 검토

1. **주민등록번호 취급**: 개인정보보호법 §24조의2에 따라 주민번호 처리는 법령에 구체적 근거가 있어야 하는데, 4대보험 취득·상실 신고는 각 보험 법령이 주민번호 기재를 요구하므로 **신고 목적 처리 자체는 적법**. 다만 사설 API에 주민번호를 전달해 조회시키는 경우 **개인정보 처리위탁(§26)** — 위탁계약서(재위탁 제한, 목적 외 처리 금지, 안전조치)와 개인정보처리방침 위탁 고지가 필요. 테넌트(사업장)와 우리, 우리와 API 업체 간 2단 위탁 구조 문서화 필수.
2. **스크래핑 적법성**: 금융권 마이데이터(신용정보법 개정)에서는 스크래핑이 금지됐지만, **공공기관(공단) 대상 사업장 정보 스크래핑은 신정법 적용 대상이 아니어서 현행법상 금지 규정 없음** — 다만 개인정보보호위원회가 의료 마이데이터 관련해 "스크래핑 대신 공식 API 연계" 권고를 낸 바 있어(2025.5 보도) **정책 방향은 스크래핑 축소** [확인]. 중장기 규제 리스크로 인지할 것.
3. **공동인증서 위임 보관**: 사업장 인증서(파일+비밀번호)를 우리 서버/API 업체에 저장하는 것은 전자서명법상 명시적 금지는 없으나, 유출 시 책임이 크고 이용약관 위반 소지가 있는 그레이존 [추정]. 완화책: (a) 틸코식 간편인증(건별 본인 인증), (b) 인증서를 우리가 보관하지 않고 CODEF Connected ID에만 등록(암호화 저장은 업체 책임), (c) 조회 전용 위임.
4. **노무사 대행 신고의 위임 구조** [확인]:
   - 건강보험·국민연금: **EDI 업무대행기관 지정**(edi.nhis.or.kr 신고신청 업무대행 지정/해지 신청서, 민법 §114 대리) — 사업장이 위임장 제출 → 우리 EDI 계정에서 수임사업장 신고 가능.
   - 고용·산재: **보험사무대행기관**(고용산재보험료징수법 §33, 노무사·세무사 등) 인가 → 토탈서비스에서 수임사업장 일괄 신고.
   - 이 구조가 "제출 자동화"의 법적 기반이며, 사설 API 없이도 우리 계정 1개로 다수 테넌트 신고를 합법 처리할 수 있음.

## 5. 경쟁 급여 SaaS의 4대보험 처리 방식

| 서비스 | 방식 | 근거 |
|---|---|---|
| **뉴플로이/알밤** | RPA 기반 자동화 + 취득·상실 신고서를 **관할 공단에 온라인 팩스로 접수**. 노무/세무대리인 초대 기능, 대리인 없으면 사업주가 직접 팩스 발송 [확인] | newploy.net |
| **자비스(Jobis)** | 플랫폼에서 "4대보험 신고 요청" → **담당 세무대리인이 검토 후 대행 신고**. 일용직 근로내용확인신고도 세무대리인이 익월 15일까지 제출. 공단 처리 완료 여부는 확인 불가 고지 [확인] | help.jobis.co |
| **flex** | **Payroll Partners**(급여 전문가/BPO 제휴)가 4대보험·원천세·연말정산까지 수행 [확인] | flex.team 블로그 |
| **ZUZU(주주)** | 가이드 제공 중심(EDI/팩스 안내) [확인 수준 낮음] | zuzu.network |

시사점: **시장 선두들도 '공식 제출 API'가 없어서 팩스 RPA 또는 인적 대행으로 처리** 중. 우리는 노무사 사무소 직영이라는 강점(대행기관 지위 직접 보유 가능)이 있어 자비스·flex 모델을 내재화할 수 있다.

## 6. 추천안

**Phase 1 조회 API = CODEF 채택 (PoC 병행: 하이픈)**

근거:
- 필요 상품 2종(정보연계센터 사업장 가입자명부, 통합징수포털 완납/고지)을 모두 보유하고, **공식 Python SDK + 무료 데모 샌드박스**로 개발 리스크가 가장 낮다.
- 12월 1만 사업장 목표 시 대량 트래픽·안정성 실적(구독형 플랫폼 최대 규모 표방)이 중요 — 쿠콘도 동급이지만 계약 문턱이 높고, 틸코는 사업장 단위 상품 폭이 좁다.
- 단, CODEF 정식 단가가 비공개이므로 **계약 협상 전 하이픈 비즈머니(월 10만+건당, 무계약 즉시 시작)로 실데이터 PoC**를 돌려 건당 원가 기준점을 잡고 협상 지렛대로 쓴다. 하이픈의 "개인별 산출내역" API는 고지 대사에 특히 적합하므로 Phase 2 대사용으로는 하이픈이 최종 채택될 수도 있다(듀얼 벤더 허용).

**제출 자동화 = 사설 API 아닌 대행기관 구조 + RPA**: §4-4 위임 구조를 정식화하고, EDI 화면 자동화(agent-browser)는 내부 운영 도구로만(공단 약관·안정성 리스크 때문에 테넌트 노출 금지).

## 7. 단계별 연동 플랜

### Phase 1 — 자격/가입내역 조회 (목표: +1~2개월)
1. CODEF 데모 계정 + `easycodefpy`로 가입자명부 API 검증(noho 테넌트 실인증서, 사업주 동의 후).
2. 신규 모듈 `hrms/regional/south_korea/insurance_inquiry_api.py` (filing과 분리):
   - `fetch_workplace_subscribers(company, management_number)` → CODEF 호출 → 결과를 새 DocType `Insurance Subscriber Snapshot`(조회일자, 관리번호, 직원 매칭 키=암호화 주민번호 해시)으로 저장.
   - 인증서/Connected ID는 테넌트별 암호화 필드(기존 주민번호 암호화 패턴 재사용), API 키는 site_config.
   - `insurance_filing_api`와 동일한 **fail-closed 게이트**(사업주 동의 플래그 없으면 조회 차단) 적용.
3. HRMS 직원 명부 vs 공단 명부 diff 리포트(누락 취득/상실 감지) — 이것만으로도 노무사 실무 가치 큼.

### Phase 2 — 고지보험료 대사 (+2~3개월)
1. 통합징수포털 고지내역/개인별 산출내역 API(CODEF 또는 하이픈 seq=80 계열) 연동.
2. `reconcile_insurance_billing(company, period)`: 우리 급여 엔진 계산 공제액 vs 공단 고지액을 직원(주민번호 해시)·보험별로 대사 → 차액 리포트. 쿠우쿠우 국민연금 4.75% 역산 같은 케이스를 시스템으로 잡는 기능.
3. Salary Slip 검증 훅에 "공단 고지 불일치 N건" 경고 배지.

### Phase 3 — 제출 반자동화 (+3~6개월)
1. 우리 사무소를 건보/연금 EDI 업무대행기관 + 고용산재 보험사무대행기관으로 등록(이미 보유 시 수임 확대).
2. 테넌트 온보딩에 위임장 수취 플로우 추가 → `workplace_management_number`별 수임 상태 필드.
3. `generate_insurance_filing` 산출 xlsx → 내부 제출 큐(신규 DocType `Insurance Filing Submission`, 상태: draft→approved→submitted→confirmed) → 운영자가 EDI/토탈서비스 일괄 업로드. RPA(브라우저 자동화)는 내부 도구로 점진 도입.
4. 제출 결과(접수번호·처리결과)를 Phase 1 조회 API로 역검증(취득신고 후 명부에 반영됐는지 자동 확인) — 이것이 진짜 "폐루프".

### 규모 경제 참고
1만 사업장 × 월 1회 명부 조회 = 월 1만 콜. 건당 100~500원 가정 시(단가 [미확인]) 월 100만~500만원 → **조회 주기 차등(이벤트 기반: 입퇴사 발생 시에만 조회)** 설계로 비용 통제 필요.
