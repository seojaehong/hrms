# SafeClaw HR — Product Requirements Document (v2)

**프로젝트명**: SafeClaw HR
**문서 버전**: v2.0 (North Star Vision)
**작성일**: 2026-07-10

---

## 0. 이름이 담고 있는 세 겹의 의미

**SafeClaw**는 단일 의미가 아닌 세 겹의 의미를 동시에 품고 있는 이름입니다.

첫 번째는 **Safe + Claw**, 즉 안전한 발톱입니다. 날카롭지만 통제된 집행력을 의미하며, 중대재해처벌법이라는 날카로운 법적 요구를 안전하게 다룬다는 제품 철학을 담고 있습니다. 두 번째는 **Safe HR**, 안전한 인사 시스템이라는 직관적인 제품 포지셔닝입니다. 세 번째이자 가장 핵심적인 층위는 **OpenClaw의 Claw**입니다. 에이전트 오케스트레이션 프레임워크인 OpenClaw의 철학을 계승하면서, 그것을 HR과 안전 도메인에 특화시킨 버전이라는 기술적 선언입니다.

---

## 1. 제품 비전 (North Star)

SafeClaw HR의 궁극적인 목표는 **"온톨로지 기반 하네스 엔지니어링으로 작동되는 안전 에이전트 자동화(Safety Agent Automation)"** 시스템을 구축하는 것입니다.

이는 기업의 가장 큰 리스크인 산업안전보건법 및 중대재해처벌법 관련 요구사항을 시스템적으로 방어하고, 관련된 모든 문서 생성, 유기적 연동, 현장 전파를 에이전트가 오케스트레이션하는 것을 의미합니다. 이 과정에서 LLM은 자의적 판단을 내리지 않으며, 철저히 검증된 명시적 온톨로지(법률 및 사규 규칙)와 하네스(안전 게이트) 통제 하에서만 동작합니다.

## 2. 기술 DNA 및 포지셔닝

SafeClaw HR은 단순히 AI를 붙인 HR 소프트웨어가 아닙니다. 에이전트 오케스트레이션 분야의 두 계보를 계승하여, 한국 노동법과 산업안전 도메인에 최초로 특화 임베딩한 산업용 에이전트 플랫폼입니다.

```
OpenClaw
  └── 철학 계승: 에이전트 오케스트레이션, 하네스 설계 원칙
        │
        ▼
Hermes Agent  (Nous Research, MIT License)
  └── 포크 → SafeClaw 전용 런타임으로 변환
        │  - HermesProvider 어댑터 (OpenAI 호환 ↔ agent_loop 계약 변환)
        │  - 독립 런타임 (uv standalone py3.12, 의존성 격리)
        │  - 키 라우팅 (테넌트 BYOK → 플랫폼 키 폴백, billing 태그)
        │  - /v1/runs + approval 엔드포인트 → SafeClaw 하네스 게이트 연결
        ▼
SafeClaw HR
  └── Hermes 런타임 + MCP 서버 + Frappe DB
      + 한국 노동법 온톨로지
      + 중대재해처벌법 하네스
      + 다채널 연동 (슬랙·구글챗·텔레그램·카카오)
```

### 2.1. OpenClaw에서 계승한 것

OpenClaw는 코드를 직접 가져오는 것이 아니라 **아키텍처 사고방식**을 계승합니다. 에이전트가 도구(Tool)를 선택하고, 사람이 확정하며, 하네스가 경계를 지킨다는 설계 원칙이 SafeClaw의 모든 레이어에 관통합니다.

### 2.2. Hermes에서 포크한 것

Hermes Agent(Nous Research, MIT 라이선스)는 SafeClaw의 실행 엔진입니다. 원본 소스를 그대로 보존하면서(`MIT © Nous Research` 표기 유지), 다음 네 가지를 SafeClaw 전용으로 변환합니다.

| 변환 대상 | 원본 Hermes | SafeClaw 변환 내용 |
| :--- | :--- | :--- |
| **Provider 어댑터** | OpenAI 호환 API | `HermesProvider` — SafeClaw `agent_loop` 계약으로 변환 |
| **런타임 격리** | 호스트 Python 의존 | `uv` standalone py3.12.13 venv, 의존성 완전 격리 |
| **키 라우팅** | 단일 API 키 | 테넌트 BYOK(`agent_llm_api_key`) → 플랫폼 키 폴백, billing 태그 귀속 |
| **승인 게이트** | `/v1/runs` + approval 엔드포인트 | SafeClaw 하네스 `tool_registry` 소유 — 모델이 승인을 지어내도 차단 |

## 3. 핵심 아키텍처 원칙

SafeClaw HR은 신뢰성(Trust)과 안전성(Safety)을 보장하기 위해 다음 4가지 원칙을 아키텍처 수준에서 강제합니다.

**원칙 1 — 데이터 레이어의 절대 권위 (Frappe DB)**
모든 확정 데이터와 테넌트 히스토리는 Frappe 데이터베이스에 저장됩니다. 에이전트는 이 데이터베이스를 직접 수정할 수 없으며, 모든 상태 변경은 승인 대기열(Draft)을 거쳐야 합니다.

**원칙 2 — 도구 인터페이스와 테넌트 격리 (MCP 서버)**
에이전트는 `mcp_server/http_server.py`를 통해서만 시스템과 상호 작용합니다. 테넌트 격리는 Bearer 토큰 기반 바인딩 파일로 엄격히 통제되며, 크로스 테넌트 접근은 구조적으로 불가능합니다.

**원칙 3 — 안전 게이트 (Harness Engineering)**
에이전트의 모든 출력은 `no_mutation_performed`, `requires_human_approval: true` 계약을 준수해야 합니다. 확정 행위(결재, 외부 발송, DB 커밋)는 반드시 사람(운영자 또는 노무사)의 명시적 승인을 필요로 합니다. 승인 게이트는 Hermes의 approval 엔드포인트를 SafeClaw `tool_registry`가 소유하여 통제합니다.

**원칙 4 — 명시적 지식 엔진 (Explicit Ontology)**
LLM의 환각(Hallucination) 리스크를 원천 차단하기 위해, 현재 파이썬 코드 내에 암묵적으로 존재하는 지식(`statutory_2026.py`, `severance_pay.py` 등)을 명시적 온톨로지 구조로 승격시킵니다. 에이전트는 이 온톨로지 트리를 따라 추론하며, 자동 자가 수정(Self-correction)이나 통제되지 않은 학습은 배제합니다.

## 4. 단계별 로드맵 (Phased Roadmap)

### Phase 1 — 기반 통합 및 에이전트 임베딩 (단기)

**목표**: 에이전트가 HRMS 데이터에 안전하게 접근하여 질의에 답변하고, 초안을 생성하는 파이프라인 완성.

로컬에 구현된 Hermes 포크(HermesProvider, 독립 런타임, 키 라우팅, 승인 게이트 배선)를 원격 레포지토리에 안전하게 통합합니다(시크릿 스캔 완료 후). 이와 함께 현재 구축된 5개 채널(슬랙, 구글챗, 텔레그램, 카카오, 메일)을 통해 에이전트 기반의 안전한 데이터 읽기(Read-only) 및 초안 생성을 실전화합니다.

현재 `ai_chat.py`는 검색(Retrieval) 기반의 1세대 구현입니다. 이 단계에서 Hermes 런타임을 연결하여 자연어 대화 기반의 2세대 AI 챗으로 승격시킵니다. 단, 모든 계산과 법률 판단은 여전히 MCP Tool 호출(Python 로직)로 강제합니다.

**완료 기준**: `korea_agent_harness_provider="hermes"` 설정으로 급여 처리 스킬이 MCP 도구를 호출하고, 최종 승인 게이트에서 사람의 확인을 기다리는 상태까지 실동.

### Phase 2 — 암묵적 지식의 온톨로지화 (중기)

**목표**: 에이전트가 "왜 이런 계산이 나왔는지"를 온톨로지 트리를 따라 역추적(Traceability)하여 설명할 수 있는 체계 구축.

현재 파이썬 코드 내에 암묵적으로 존재하는 법정 요율(`statutory_2026.py`), 퇴직금 계산 로직(`severance_pay.py`), 연말정산 로직(`year_end_settlement.py`)을 규칙 기반 온톨로지(Rule-based Ontology)로 분리 및 모델링합니다. 온톨로지의 첫 번째 노드는 이미 `annual_leave.py`와 `leave_allocation_adapter.py`가 구현된 **근로기준법 제60조(연차)**로 시작하는 것이 가장 현실적입니다.

LLM Wiki 및 Diff Queue 개념을 도입하여, 법령 개정 시 에이전트가 변경 제안(Diff)을 생성하고 사람이 이를 승인하는 워크플로우를 구축합니다. 단, 자동 자가 수정(Self-correction)이나 자동 학습 승격은 이 단계에서도 배제합니다.

**완료 기준**: 에이전트가 연차 계산 결과를 반환할 때, 근거 법조항(근로기준법 제60조 제1항)과 적용 사규 조항을 함께 인용하는 Explainable 응답 생성.

### Phase 3 — 중대재해처벌법 및 산업안전보건법 자동화 (장기/북극성)

**목표**: HR 도메인을 넘어 안전 보건 도메인으로 확장하여, 기업의 법적 리스크를 시스템적으로 방어하는 규제 준수(Compliance) 자동화 달성.

`compliance_checklist.py`를 고도화하여 중대재해처벌법 요구사항(안전보건관리체계 구축, 위험성 평가, 도급 관리 등)을 온톨로지로 매핑합니다. 에이전트는 정기 점검 일정에 따라 체크리스트를 실행하고, 미비 사항을 발견하면 담당자에게 알림을 발송하며 보완 문서 초안을 생성합니다.

외국인 근로자를 위한 다국어 번역 파이프라인(`foreign_worker.py` 확장)을 구현하여, 안전교육 자료를 현장 근로자의 모국어로 자동 번역하고 카카오 알림톡이나 구글챗을 통해 개별 발송합니다. 수신 및 열람 확인(Read Receipt)까지 추적하여 법적 증빙 자료로 보관합니다.

**완료 기준**: 중대재해처벌법 제4조(사업주의 의무) 요구사항 체크리스트를 에이전트가 자동 실행하고, 미비 항목에 대한 보완 문서 초안을 생성하여 노무사 승인 큐에 적재하는 플로우 실동.

## 5. 핵심 기능 명세 (Feature Specifications)

### 5.1. Hermes 포크 기반 에이전트 런타임

SafeClaw 전용으로 변환된 Hermes 런타임은 다음 계약을 준수합니다. 에이전트가 어떤 LLM을 사용하든, 어떤 도구를 호출하든, 최종 확정 행위(Mutation)는 반드시 `tool_registry`가 소유한 승인 게이트를 통과해야 합니다. 모델이 승인을 자의적으로 생성하더라도 하네스가 이를 차단합니다.

### 5.2. 온톨로지 기반 추론 엔진

법령(근로기준법, 중처법), 사규(취업규칙), 개별 근로계약, 실제 근태/급여 데이터를 연결하는 지식 그래프입니다. 에이전트는 내장된 LLM 가중치 지식이 아닌 이 온톨로지 엔진(MCP Tool)에 질의하며, 반환된 결과는 산출 근거(관련 법조항 및 사규 조항)와 함께 제공되어 완전한 설명 가능성(Explainability)을 보장합니다.

### 5.3. 하네스 기반 승인 게이트

에이전트의 모든 상태 변경 요청을 가로채는 중간 검문소입니다. 에이전트가 작업을 완료하고 결재 상신을 시도하더라도, 시스템은 이를 `Draft` 상태로만 저장하고 `requires_human_approval` 플래그를 활성화하여 대기열(Diff Queue)에 적재합니다. 최종 승인은 반드시 권한을 가진 사람(운영자, 노무사)에 의해 이루어집니다.

### 5.4. 다국어 안전 문서 전파 파이프라인

중대재해처벌법에 따른 정기 안전교육이나 공지사항 발생 시, 에이전트가 한국어 원본 초안을 작성합니다. 관리자의 승인이 떨어지면, 시스템은 대상 근로자의 국적 데이터를 파악하여 적절한 언어로 자동 번역합니다. 번역된 문서는 알림톡이나 사내 메신저를 통해 개별 발송되며, 수신 및 열람 확인(Read Receipt)까지 추적하여 법적 증빙 자료로 보관합니다.

## 6. 리스크 및 완화 전략 (Risk & Mitigation)

| 리스크 | 설명 | 완화 전략 |
| :--- | :--- | :--- |
| **LLM 환각** | LLM이 존재하지 않는 법률이나 잘못된 계산식을 창작 | 모든 핵심 계산 및 법률 판단은 MCP를 통한 온톨로지 엔진(Python 로직) 호출로 강제. LLM은 결과를 자연어로 포장하는 역할만 수행. |
| **권한 남용** | 에이전트가 임의로 급여를 확정하거나 민감 문서를 외부로 발송 | 하네스 레이어에서 `no_mutation_performed` 원칙 강제. 모든 상태 변경은 Human-in-the-loop 기반의 승인 큐를 거치도록 아키텍처 수준에서 차단. |
| **테넌트 데이터 유출** | 에이전트가 A 테넌트의 정보를 B 테넌트 사용자에게 노출 | Bearer 토큰 기반 바인딩 및 Frappe Site 격리 아키텍처를 엄격히 유지. 크로스 테넌트 접근 원천 차단. |
| **법령 업데이트 지연** | 개정된 중대재해처벌법이나 노동법이 시스템에 미반영 | LLM 워커가 법제처 API를 모니터링하여 온톨로지 변경 제안(Diff)을 생성하고, 관리자의 검토 및 승인을 유도. |
| **Hermes 포크 유지 비용** | 업스트림 Hermes 업데이트 추적 부담 | MIT 라이선스 표기 유지 + 변환 레이어(HermesProvider)를 명확히 분리하여 업스트림 변경의 영향 범위를 최소화. |

## 7. 결론

SafeClaw HR은 OpenClaw의 철학을 계승하고, Hermes의 실행 엔진을 포크하여, 한국 노동법 온톨로지와 중대재해처벌법 하네스로 감싼 **세계 최초의 산업 특화 에이전트 HR 플랫폼**입니다.

단기적으로는 급여와 근태의 안전한 관리에서 출발하지만, 궁극적으로는 기업의 생존을 위협하는 중대재해처벌법 및 노동법 리스크를 시스템적으로 방어하는 전사적 안전망으로 진화할 것입니다. 이 제품의 경쟁 우위는 기능의 수가 아니라 **"법률적 안전성이 수학적으로 증명된 에이전트"** 라는 신뢰 구조 자체에 있습니다.
